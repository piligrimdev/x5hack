# AI Product Discovery

Преобразуй тему, описание продукта, URL или материалы интервью в прослеживаемую цепочку продуктовых решений. Скилл адаптирован из n8n-сценария `AI_Product_Discovery.json`; выполнять исходные узлы n8n не требуется.

## Начало работы

- Определи продукт/направление, целевой рынок, доступные исследования и требуемый результат из запроса и файлов. Если сам объект исследования отсутствует, спроси только о нём.
- По умолчанию отвечай на языке пользователя. Английский и строгий JSON из исходного workflow нужны только при соответствующем запросе или интеграции.
- Для полного discovery пройди цепочку ниже. Для отдельного этапа используй имеющиеся входные данные, не запускай весь процесс заново.
- Сайт существующего продукта анализируй напрямую; для направления сначала найди подходящие коммерческие продукты. Масштаб исследования соотнеси с запросом, а при отсутствии заданного масштаба обозначь небольшой первоначальный список.
- Для актуальных сведений используй доступный поиск и открывай первичные источники. Сохраняй URL продукта отдельно от URL источника и передавай идентификаторы продукта и сегмента через все этапы.
- Когда пользователь просит первые пять шагов презентации, используй [воронку «сигнал → аналоги → выбор → сравнение → выбор функций»](references/analogue-feature-funnel.md) и останавливайся в точках продуктового выбора.

## Процесс

1. **Продукты.** Зафиксируй предложение, аудиторию, сценарии использования, альтернативы и подтверждение коммерческого предложения. Страница тарифов подтверждает предложение к покупке, но не число продаж или выручку. Не превращай каждую поисковую цитату в отдельный продукт. Если сайт недоступен, явно обозначь пробел.
2. **Сегменты.** Для каждого продукта выдели до пяти различимых сегментов и по одному предложению о выгоде. Не дополняй список выдуманными сегментами ради количества. Присвой стабильные ID.
3. **ICP.** Для каждого исследуемого сегмента опиши тип клиента, отрасль, демографию/фирмографию, географию, психографику, поведение, потребности, триггеры покупки, принятие решения, бюджет, каналы и возражения. Неприменимые поля отметь; неизвестные значения оставь неизвестными либо назови допущением.
4. **Интервью.** Если есть реальные записи — анализируй их. Иначе подготовь 8–10 вопросов и, в режиме полного discovery по этой методике, модельные ответы с явной пометкой «Синтетическое интервью — гипотезы для проверки». Не изображай контакт с реальным клиентом. Сохраняй Q/A ID и происхождение интервью.
5. **Карта болей.** Выдели обычно 4–8 болей, если материал это позволяет. Для каждой укажи корневую причину, обходные решения, желаемый результат, цитаты и оценки из [модели данных](references/data-model.md). Цитаты из синтетического интервью остаются синтетическими и не подтверждают реальный спрос.
6. **JTBD.** Сформулируй обычно 3–6 работ на сегмент: «Когда [ситуация], я хочу [мотивация], чтобы [результат]». Добавь барьер, измеримые желаемые результаты без привязки к конкретному решению, силы переключения, критерии успеха и момент прогресса. Свяжи работы с конкретными болями.
7. **Value Proposition Canvas.** Сопоставь функциональные, социальные и эмоциональные работы, боли и выгоды с продуктами/услугами, способами устранения болей и создания выгод. Отличай существующие функции продукта от предлагаемых.
8. **Гипотезы.** Подготовь минимум пять различимых гипотез на исследуемую JTBD в полном режиме; для узкого запроса следуй его объёму. Каждая содержит сегмент, связь с болью/JTBD, предлагаемое изменение, обоснование, метрику, ожидаемый эффект и способ проверки через MVP или эксперимент. Числовая цель — предложенный критерий, если пользователь не дал её как факт.
   Перед RICE проведи [evidence-aware triage](references/hypothesis-triage.md): найди главное рискованное допущение, дубликаты, логические противоречия и гипотезы, которые пока невозможно различить экспериментом. Не удаляй идеи без записи причины.
9. **RICE.** Оцени и сравни гипотезы на общем горизонте. Сохрани полный рейтинг, выдели лидера для каждой JTBD и при сопоставимых оценках общего лидера. Правила и вычисление — в [RICE](references/rice.md). Один сгенерированный текст не повышает достоверность другого. Если цифр нет, рейтинг является предварительным сценарием.
10. **Lean Canvas.** Для выбранной гипотезы заполни 12 полей из [модели данных](references/data-model.md). В полном режиме можно дать canvas лидеров по JTBD и выделить один итоговый. Не придумывай доказанное конкурентное преимущество, доходы или размеры рынка; неизвестное преврати в вопрос для проверки.

## Передача выбранной гипотезы в разработку

Переходи к этому разделу только после явного выбора пользователем гипотезы и минимального scope. Подготовь [implementation handoff](references/implementation-handoff.md), сохраняя статусы доказательств и открытые продуктовые решения. Не превращай предварительный RICE или рекомендацию агента в решение пользователя.

Discovery не обязан автоматически создавать API, схему БД, технические задачи или код. Если пользователь просит спецификацию либо реализацию выбранной функции, используй `spec-driven-feature`: сначала перенеси продуктовый контракт, затем уточни технические границы и проверь соответствие реализации.

## Работа с доказательствами

Используй статусы `observed`, `inferred`, `synthetic`, `unknown` для содержательных утверждений и оценок. Ссылки и реальные интервью поддерживают только те утверждения, которые в них действительно есть. Количество сгенерированных интервью не является выборкой. При переносе боли в JTBD, гипотезу и canvas сохраняй её статус и ссылки.

## Результат

- В полном режиме сохрани `discovery.md` и `discovery.json` в согласованной папке результатов; при отсутствии указания используй отдельную папку внутри текущего проекта. Для одного небольшого этапа достаточно ответа в чате, если файл не запрошен.
- Отчёт содержит объект и границы исследования, источники, результаты этапов, полный рейтинг, выбранную гипотезу, Lean Canvas, неизвестные и ближайший эксперимент. Структурированный файл следует [модели данных](references/data-model.md).
- Проверь связь продукт → сегмент → боль → JTBD → гипотеза → canvas, происхождение цитат, формулы, единицы и соответствие победителя рейтингу.
- По запросу перенеси материалы в Miro через доступный MCP: сначала подготовь содержимое, прочитай целевую доску, затем добавь отдельные подписанные фреймы с источниками и статусами. При отсутствии ссылки спроси о целевой доске или создай новую только по запросу. Само наличие подключения не означает запрос публикации.
- При недоступном MCP оставь готовые локальные материалы и укажи, какой шаг не выполнен. Google Docs/Slides и Miro не обязательны для работы скилла.

Подробности адаптации исходного сценария: [source-mapping.md](references/source-mapping.md).
