# RICE

RICE = reach × impact × confidence / effort.

- Reach: уникальные пользователи или команды за единый период; по умолчанию месяц. Не смешивай пользователей с командами в одном рейтинге. Для сценарного моделирования исходник предлагает 100 / 500 / 2000 / 10000; это допущения, а не рыночные данные. Подтверждённый нулевой охват допустим.
- Impact: 0.25 / 0.5 / 1 / 2 / 3 — минимальный / низкий / средний / высокий / очень высокий. Объясни связь с метрикой.
- Confidence: 0–1. Опирайся на независимые доказательства. Синтетическое интервью не подтверждает частоту боли или охват. Если используешь исходное значение 0.5 при отсутствии данных, пометь его как сценарное допущение.
- Effort: человеко-недели, минимум 0.5, шаг 0.5. Исходные ориентиры для допущений: текст/настройка 0.5–1; средняя функция/UX 2–4; инфраструктура/ML 6–10. Их следует уточнять по продукту.
- Неизвестный фактор оставь null, если обоснованный сценарий не выбран. Такая строка не ранжируется и не побеждает строку с вычисленным результатом.

Для воспроизводимого вычисления используй:

```sh
python3 scripts/rank_rice.py input.json output.json
```

Пути скрипта разрешай относительно папки скилла. Вход — массив объектов с уникальным `id`, `hypothesis`, числовыми `reach`, `impact`, `confidence`, `effort`, четырьмя `rationale_reach`, `rationale_impact`, `rationale_confidence`, `rationale_effort`. Сохрани также `evidence_status`, `source_ids` и область сравнения. Скрипт сохраняет дополнительные поля.

Сортировка по исходному RICE по убыванию, затем Impact, Reach по убыванию и Effort по возрастанию. Отображаемый RICE округляется до одного знака; округление не меняет порядок. Строки с null идут в конец. При одинаковых факторах сохраняется исходный порядок.

Сохрани полный рейтинг даже если отчёт показывает одного победителя. Выбор одного победителя на JTBD сохраняет логику исходного n8n-сценария; общий победитель требует сопоставимых единиц и периода.
