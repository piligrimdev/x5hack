## [MAIN] Схема БД для MVP лояльности X5

### Контекст
- MVP механики: аватар, персональный челлендж по истории чеков, рейтинг экономии
- ИИ-модуль: LLM генерирует персональные рекомендации на синтетических данных
- Приоритет: офлайн покупки, retention через видимую экономию + соц. сравнение

### Схема (предложенная)
- Товар: id, название, цена, категория_id, бренд_id
- Скидка: id, процент, тип_скидки_id, тип_связи_id, id_связанной_сущности
- Сегмент: id, название (подросток/семьянин/пожилой)
- Карта лояльности: id, уровень_лояльности, контакты, сегмент_id
- Чек: id, дата, uid_карты_оплаты, карта_лояльности_id
- Позиция чека: товар_id, кол-во, скидка_id
- Индивидуальные задания: id, юзер_id, описание (JSON?)

### Проверочные задачи
1. Отслеживание экономности (персональный челлендж)
2. Доступность для аналитиков
3. Retention / цикл посещений магазина

## Ideas Generated
- Скидки: best-price-wins (не стекаются, выбирается минимальная цена)
- Позиция чека: base_price_at_purchase + paid_price + discounted_amount (снимает проблему мутации цен и скидок)
- Скидка: добавить scope (all/by_format/by_store) + valid_from/valid_to
- M2M магазин-скидка для store-specific промо
- Составные задания: таблица task_progress (task_id, criterion_id, current_value, target_value)
- Задание: universal criterion_type (по кол-ву товаров / сумме / кол-ву визитов)
- Магазин: геокластер как свойство магазина → район пользователя по транзакции, а не по адресу

## Provocative Questions Explored
- Что если задание multi-criteria? (купи 3 йогурта И 1 хлеб)
- Что при возврате товара? Нужен ли refunded флаг на позиции?
- Оплата апельсинками: это скидка или отдельный способ оплаты?
- Что если scope=by_store, но M2M пуст → ошибка конфигурации?
- Какой timezone для valid_from/to?
- Скидки по дням недели или времени суток — нужен ли is_recurrent + schedule?

## Final Summary

### Key Themes
1. **Снимок данных на момент покупки** — цены и скидки меняются; три поля в позиции чека (base/paid/discounted) делают историю неизменяемой
2. **Скидки: гибкость scope + временны́е рамки** — область действия (all/format/store) + valid_from/to + best-price-wins в бизнес-логике
3. **Задания со структурированным критерием** — вместо свободного JSON: тип (product/category/brand) + entity_id + quantity; прогресс обновляется автоматически при чеке
4. **Магазин как носитель геоконтекста** — geo_cluster на магазине, а не адрес на пользователе; безопасно и достаточно для рейтинга района
5. **Чёткая граница PoC vs Backlog** — апельсинки, аватар, районный рейтинг, купоны, фрод осознанно отложены
