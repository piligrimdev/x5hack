# Feature Specification: Реферальная программа

**Feature Branch**: `011-referral-program`

**Created**: 2026-09-06

**Status**: Draft

**Input**: User description: "Добавим функцию реферальной программы. У пользователя есть возможность пригласить друга в программу лояльности: отправить реферальный код (всегда генерируется разный), который приглашённый вводит при логине (реактивация аккаунта после таймаута / регистрация). Реактивация — возврат уже зарегистрированного пользователя обратно в сеть; доступна только если у него нет покупок за последние полгода, иначе ошибка при логине с реферальным кодом. Регистрация с реферальным кодом всегда доступна. Приглашающий получает купоны на крутки и кешбек (размер в настройках) только если приглашённый совершил покупку в течение недели после активации кода. Приглашённый получает скидку X% (в настройках) на неделю после активации."

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Сгенерировать и отправить уникальный реферальный код (Priority: P1)

Авторизованный держатель карты лояльности хочет пригласить друга. За одно действие от главного экрана он открывает приглашение, получает новый реферальный код и копирует или отправляет его удобным способом (системный «поделиться» или копирование в буфер). Каждый запрос на новый код выдаёт другое значение: один и тот же код нельзя получить повторно.

Код — короткий, его можно продиктовать или вставить при входе. Неиспользованные ранее выданные коды остаются действительными: приглашающий может раздать разные коды разным друзьям.

**Why this priority**: Без кода нет приглашения. Это единственная точка, с которой стартует вся цепочка.

**Independent Test**: Авторизованный пользователь запрашивает код дважды подряд. Получает два разных значения. Оба можно скопировать. Повторный запрос не перезаписывает уже выданные неиспользованные коды.

**Acceptance Scenarios**:

1. **Given** авторизованный держатель карты лояльности на главном экране, **When** он открывает приглашение друга, **Then** система выдаёт новый уникальный код, и пользователь может скопировать или отправить его за одно действие на этом экране.
2. **Given** пользователь уже получил код A, **When** он запрашивает ещё один код, **Then** система выдаёт код B, отличный от A и от всех ранее выданных кодов; код A остаётся действительным, пока его не активировали.
3. **Given** два разных пользователя, **When** оба генерируют коды, **Then** ни один код не совпадает с другим.
4. **Given** неавторизованный пользователь, **When** он пытается получить код, **Then** запрос отклоняется.

### User Story 2 — Зарегистрироваться с реферальным кодом (Priority: P1)

Новый пользователь на экране входа вводит номер телефона и (по желанию) реферальный код друга. Регистрация с валидным кодом всегда проходит: аккаунт создаётся, код однократно активируется, у приглашённого сразу открывается недельное окно персональной скидки X%.

Код необязателен: регистрация без кода работает как раньше и не даёт реферальной скидки.

**Why this priority**: Это основной путь привлечения нового участника. Пока код нельзя ввести при регистрации, приглашение бесполезно.

**Independent Test**: Создать код у пользователя A. Зарегистрировать нового пользователя B с этим кодом. B получает активную скидку на 7 дней. Повторная регистрация с тем же кодом отклоняется (код уже использован).

**Acceptance Scenarios**:

1. **Given** новый номер телефона и действительный неиспользованный код пользователя A, **When** человек регистрируется с этим кодом, **Then** аккаунт создаётся, код помечается активированным, у нового пользователя стартует скидка X% на 7 дней с момента регистрации.
2. **Given** новый номер телефона без кода, **When** человек регистрируется, **Then** аккаунт создаётся как обычно, реферальная скидка не выдаётся.
3. **Given** новый номер и несуществующий, уже использованный или собственный код приглашающего (если бы он совпал), **When** человек регистрируется с таким кодом, **Then** регистрация отклоняется с понятной ошибкой, аккаунт не создаётся.
4. **Given** код уже активирован другим человеком, **When** новый пользователь вводит тот же код при регистрации, **Then** регистрация отклоняется, код повторно не активируется.

### User Story 3 — Реактивировать аккаунт кодом или получить отказ (Priority: P1)

Уже зарегистрированный пользователь возвращается в программу лояльности («реактивация» — вход с реферальным кодом после долгого отсутствия покупок). На экране входа он вводит номер и код друга.

Реактивация разрешена только если у него нет ни одной покупки за последние 6 месяцев. Тогда вход проходит, код активируется, стартует недельная скидка X% — как у нового участника.

Если покупки за последние 6 месяцев есть, вход **с кодом** отклоняется с понятной ошибкой. Тот же человек может сразу войти **без кода** — обычный вход всегда доступен.

**Why this priority**: Отделяет возврат «уснувшего» клиента от злоупотребления кодом действующими покупателями. Без этого правила реферал превращается в раздачу скидок всем, у кого есть знакомый.

**Independent Test**: Пользователь C с последней покупкой 7 месяцев назад входит с валидным кодом → вход успешен, скидка активна. Пользователь D с покупкой вчера входит с валидным кодом → ошибка; вход без кода проходит.

**Acceptance Scenarios**:

1. **Given** зарегистрированный пользователь без покупок за последние 6 месяцев и действительный чужой неиспользованный код, **When** он входит с этим кодом, **Then** вход успешен, код активирован, стартует скидка X% на 7 дней.
2. **Given** зарегистрированный пользователь с хотя бы одной покупкой за последние 6 месяцев и валидный код, **When** он входит с этим кодом, **Then** система возвращает ошибку, код не активируется, сессия не выдаётся.
3. **Given** тот же пользователь с недавними покупками, **When** он входит без кода, **Then** вход проходит как обычно, реферальных бонусов нет.
4. **Given** номер, которого нет в системе, **When** человек нажимает «войти» с кодом, **Then** система сообщает, что аккаунта нет (как обычный вход), и предлагает регистрацию; код сам по себе не создаёт аккаунт на входе.
5. **Given** несуществующий или уже использованный код, **When** существующий пользователь входит с ним, **Then** вход отклоняется с понятной ошибкой, даже если по покупкам он подходит под реактивацию.

### User Story 4 — Награда приглашающему только после покупки за неделю (Priority: P1)

Приглашающий не получает ничего в момент, когда друг активировал код. Купоны на крутки колеса и кешбек начисляются **только если** приглашённый зафиксировал хотя бы одну покупку в течение 7 дней после активации. Размер обеих наград задаётся настройками программы и не меняется задним числом для уже сработавшей связки.

Одна успешная покупка в окне закрывает обязательство: повторные покупки приглашённого в ту же неделю не дают вторую пачку купонов и кешбека. Если за 7 дней покупок не было — приглашающий ничего не получает, окно закрывается.

**Why this priority**: Это экономический фильтр программы: платим за реального вернувшегося или нового покупателя, а не за ввод кода.

**Independent Test**: Активировать код. Зафиксировать покупку приглашённого на 3-й день → у приглашающего появились N купонов и кешбек на сумму из настроек, ровно один раз. Повторить сценарий без покупки 7 дней → наград нет.

**Acceptance Scenarios**:

1. **Given** активированный код и приглашённый без покупок после активации, **When** проходит меньше 7 дней и приглашённый совершает первую покупку, **Then** приглашающему атомарно начисляются купоны на крутки и кешбек в размере из настроек на момент активации; в истории купонов и баллов видны отдельные операции «за реферала».
2. **Given** приглашённый уже совершил покупку в окне и награда выдана, **When** он совершает ещё одну покупку в ту же неделю, **Then** повторного начисления приглашающему нет.
3. **Given** активированный код и ни одной покупки приглашённого, **When** с момента активации прошло больше 7 дней, **Then** приглашающий не получает ни купонов, ни кешбека; поздняя покупка это окно не открывает заново.
4. **Given** настройка купонов или кешбека изменена после активации, но до покупки приглашённого, **When** срабатывает награда, **Then** выдаются значения, зафиксированные в момент активации кода, а не новые.
5. **Given** настройка «0 купонов» и ненулевой кешбек (или наоборот), **When** срабатывает награда, **Then** выдаётся только ненулевая часть; нулевая не создаёт пустых операций.

### User Story 5 — Недельная скидка приглашённого на покупках (Priority: P2)

После успешной активации (регистрация или реактивация) приглашённый 7 дней платит меньше: на его покупки действует персональная скидка X% из настроек. Скидка видна в предварительном расчёте чека и в фактической экономии после покупки — в тех же рублях, что и остальные скидки.

По истечении 7 дней скидка перестаёт применяться. Покупки без активной реферальной скидки считаются как обычно.

**Why this priority**: Это ценность для приглашённого. Без видимой скидки на кассе и в экономии реферал не выполняет принцип «экономия в рублях».

**Independent Test**: Активировать код при X = 10. Положить товары в корзину в пределах 7 дней → в расчёте чека есть реферальная скидка 10% (если она лучше других). После 7 дней та же корзина считается без этой скидки.

**Acceptance Scenarios**:

1. **Given** приглашённый с активной реферальной скидкой X% и корзина внутри 7 дней после активации, **When** касса считает или фиксирует чек, **Then** к покупке применяется персональная скидка X%, экономия попадает в сумму экономии пользователя.
2. **Given** на ту же позицию действует другая скидка, **When** касса считает чек, **Then** применяется вариант с большей выгодой для покупателя (как в действующих правилах выбора скидки), реферальная скидка не складывается с меньшей на ту же позицию.
3. **Given** с момента активации прошло больше 7 дней, **When** касса считает чек, **Then** реферальная скидка не применяется.
4. **Given** пользователь без активированного кода, **When** касса считает чек, **Then** реферальной скидки нет.

---

### User Story 6 — Видеть статус своих приглашений (Priority: P2)

Приглашающий открывает тот же экран приглашения и видит список своих кодов: ожидает друга, друг активировал и ещё не купил, награда начислена, окно покупки истекло без покупки. Ему не нужно угадывать, сработал ли код.

**Why this priority**: Снимает неопределённость «отправил и тишина». Не блокирует ядро, поэтому ниже генерации и наград.

**Independent Test**: Сгенерировать код, активировать его вторым пользователем без покупки, затем совершить покупку. Список у приглашающего проходит состояния «ожидает» → «активирован» → «награда начислена».

**Acceptance Scenarios**:

1. **Given** приглашающий с несколькими кодами в разных состояниях, **When** он открывает экран приглашения, **Then** видит каждый код и понятный статус без персональных данных друга (без ФИО; телефон не обязателен на этом экране).
2. **Given** ни одного кода, **When** он открывает экран, **Then** видит пустое состояние и действие «создать код».
3. **Given** неавторизованный запрос списка, **When** он обрабатывается, **Then** запрос отклоняется.

---

### Edge Cases

- Пользователь вводит собственный код при регистрации или входе — запрос отклоняется, код не активируется (запрет самоприглашения).
- Два человека одновременно вводят один и тот же неиспользованный код — активируется ровно один; второй получает ошибку «код уже использован».
- Вход с кодом при недавних покупках — ошибка только из-за кода; повторный вход без кода успешен, история покупок не меняется.
- У реактивируемого пользователя были покупки ровно 6 месяцев назад — порог «нет покупок за последние 6 месяцев» считается включительно по календарным 180 дням: покупка старше 180 дней не блокирует реактивацию; покупка ровно в пределах 180 дней блокирует.
- Покупка приглашённого в последнюю секунду 7-дневного окна — считается успешной для награды приглашающего.
- Покупка с нулевой суммой к оплате (корзина полностью покрыта другими скидками/баллами) — всё равно засчитывается как покупка для награды приглашающего, если чек зафиксирован.
- Приглашённый уже имеет активную незакрытую реферальную связку (скидка ещё идёт или окно покупки для приглашающего ещё открыто) — новый код при входе/регистрации отклоняется.
- Пользователь, которого уже приглашали раньше, снова подходит под реактивацию (нет покупок 6 месяцев) — может активировать **новый** код; старая завершённая связка не мешает.
- Приглашающий потерял карту / не держатель карты лояльности — генерация кода недоступна; уже активированные связки продолжают жить по своим правилам.
- Настройки X%, числа купонов или суммы кешбека заданы некорректно (отрицательные, скидка > 100%) — программа не принимает такие значения; допустимы X от 0 до 100 включительно, купоны — целое ≥ 0, кешбек в рублях ≥ 0.
- Изменение настроек не пересчитывает уже выданные купоны, кешбек и уже применённые скидки по старым чекам.
- Отмена чека / возврат — вне скоупа этой функции: зафиксированная покупка остаётся основанием для награды приглашающего.
- Обрыв сети после генерации кода — повторный запрос даёт **новый** код, предыдущий не пропадает.
- Реферальная скидка и списание баллов на одном чеке: сначала товарные скидки (включая реферальную по правилу лучшей цены), затем кешбек баллами — как в действующих правилах баллов.

## Requirements *(mandatory)*

### Functional Requirements

#### Коды и приглашение

- **FR-001**: Держатель карты лояльности ДОЛЖЕН иметь возможность получить новый реферальный код за не более чем 2 действия от главного экрана и сразу скопировать или отправить его.
- **FR-002**: Каждый новый код ДОЛЖЕН быть уникальным среди всех когда-либо выданных кодов и отличаться от предыдущего кода того же пользователя.
- **FR-031**: Код ДОЛЖЕН состоять ровно из 6 символов: цифры `0–9` и латинские буквы верхнего и нижнего регистра (`A–Z`, `a–z`). Регистр значим: `AbC12x` и `abc12x` — разные коды. Ввод короче/длиннее или с иными символами ДОЛЖЕН отклоняться до активации.
- **FR-003**: Код ДОЛЖЕН быть одноразовым: успешная активация гасит его; повторно активировать тот же код ЗАПРЕЩЕНО.
- **FR-004**: Неиспользованные коды одного пользователя ДОЛЖНЫ оставаться действительными после выдачи следующего кода.
- **FR-005**: Система ДОЛЖНА отклонять активацию собственного кода пользователем.
- **FR-006**: Генерация кода и просмотр своих приглашений ДОЛЖНЫ требовать авторизации держателя карты лояльности.

#### Активация: регистрация и реактивация

- **FR-007**: Регистрация нового пользователя с действительным чужим неиспользованным кодом ДОЛЖНА всегда быть разрешена и ДОЛЖНА активировать код в той же операции, что и создание аккаунта.
- **FR-008**: Регистрация и вход без кода ДОЛЖНЫ работать как раньше и НЕ создавать реферальную связку.
- **FR-009**: Регистрация или вход с несуществующим, уже использованным или собственным кодом ДОЛЖНЫ быть отклонены; побочных изменений (аккаунт, сессия, погашение кода) быть не должно.
- **FR-010**: Вход уже зарегистрированного пользователя с кодом (реактивация) ДОЛЖЕН быть разрешён только если у него нет ни одной зафиксированной покупки за последние 180 дней. Иначе — ошибка, код не гасится, сессия не выдаётся.
- **FR-011**: Реактивация — это успешный вход существующего пользователя с кодом по FR-010: пользователь снова считается вернувшимся в сеть, код активируется, стартуют бонусы приглашённого.
- **FR-012**: У приглашённого в один момент ДОЛЖНА быть не больше одной активной реферальной связки. Попытка активировать второй код, пока связка не завершена, ДОЛЖНА быть отклонена.
- **FR-013**: После завершения связки (окно скидки и окно покупки для награды закрыты) пользователь МОЖЕТ снова активировать код только через реактивацию по FR-010.

#### Бонусы приглашённого

- **FR-014**: В момент активации приглашённый ДОЛЖЕН получить персональную скидку X% на 7 суток. X задаётся настройкой программы (0–100).
- **FR-015**: Значение X для конкретной связки ДОЛЖНО фиксироваться в момент активации и не меняться при последующем изменении настройки.
- **FR-016**: Скидка ДОЛЖНА применяться ко всем покупкам приглашённого внутри окна и отображаться в предварительном расчёте и в фактической экономии чека.
- **FR-017**: Выбор между реферальной и другими скидками на одну позицию ДОЛЖЕН следовать действующему правилу «побеждает большая выгода». Реферальная скидка не суммируется с меньшей скидкой на ту же позицию.
- **FR-018**: По истечении 7 суток скидка НЕ ДОЛЖНА применяться к новым покупкам.

#### Бонусы приглашающего

- **FR-019**: Приглашающий НЕ ДОЛЖЕН получать купоны или кешбек в момент активации кода.
- **FR-020**: Система ДОЛЖНА начислить приглашающему пакет награды (купоны на крутки и кешбек) тогда и только тогда, когда приглашённый совершил хотя бы одну зафиксированную покупку в течение 7 суток после активации.
- **FR-021**: Число купонов и сумма кешбека в рублях ДОЛЖНЫ задаваться настройками программы и фиксироваться в связке в момент активации.
- **FR-022**: Награда приглашающему ДОЛЖНА выдаваться ровно один раз на связку, атомарно с обработкой квалифицирующей покупки.
- **FR-023**: Кешбек приглашающему ДОЛЖЕН начисляться на его счёт баллов по тем же правилам, что и прочие начисления кешбека (рубли → баллы as-is).
- **FR-024**: Купоны приглашающему ДОЛЖНЫ увеличивать его баланс купонов колеса так же, как купоны за задание или недельную выдачу, с отдельным типом операции «за реферала».
- **FR-025**: Если к моменту квалифицирующей покупки настройка зафиксировала 0 купонов или 0 ₽ кешбека, соответствующая часть не создаётся; ненулевая часть всё равно выдаётся.
- **FR-026**: Покупка приглашённого после истечения 7 суток НЕ ДОЛЖНА начислять награду приглашающему.

#### Настройки, прозрачность, границы

- **FR-027**: Программа ДОЛЖНА читать из настроек как минимум: процент скидки приглашённого, число купонов приглашающему, сумму кешбека приглашающему в рублях.
- **FR-028**: Приглашающий ДОЛЖЕН видеть статусы своих кодов: ожидает активации; активирован, ждёт покупку; награда начислена; окно покупки истекло без покупки.
- **FR-029**: Публичные и экранные представления приглашений НЕ ДОЛЖНЫ раскрывать ФИО, адрес или иные прямые идентификаторы друга.
- **FR-030**: Сообщения об ошибках (невалидный код, код уже использован, реактивация недоступна из-за недавних покупок, самоприглашение) ДОЛЖНЫ быть понятны человеку на экране входа и не требовать «разобраться» в правилах программы.

### Key Entities

- **ReferralCode (реферальный код)**: Уникальный одноразовый код, выданный конкретным приглашающим. Состояния: выдан (ожидает), активирован, неприменим (погашен активацией). Не несёт персональных данных приглашённого, пока не активирован.
- **ReferralLink (реферальная связка)**: Факт активации кода конкретным приглашённым. Хранит приглашающего, приглашённого, момент активации, зафиксированные на момент активации X%, число купонов и сумму кешбека, срок скидки, срок окна покупки, статус награды приглашающего.
- **InviteeDiscount (скидка приглашённого)**: Персональная процентная скидка, действующая 7 суток после активации; участвует в расчёте чека как обычная персональная скидка.
- **InviterReward (награда приглашающего)**: Разовая выдача купонов и/или кешбека после квалифицирующей покупки приглашённого; ссылается на связку и на операции в счетах купонов и баллов.
- **User / Receipt**: Существующие сущности. Покупки за 180 дней определяют право на реактивацию; покупка после активации — условие награды приглашающему.
- **CouponAccount / PointsAccount**: Существующие счета. Награда приглашающего пополняет их, не вводя отдельную валюту.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Держатель карты получает новый уникальный код и может скопировать или отправить его не более чем за 2 действия от главного экрана и менее чем за 10 секунд.
- **SC-002**: 100% успешно выданных кодов уникальны; вероятность коллизии при обычном пользовании программой равна нулю в рамках наблюдаемых выдач.
- **SC-003**: 100% регистраций с валидным чужим неиспользованным кодом завершаются активацией и стартом скидки приглашённого.
- **SC-004**: 100% попыток входа с кодом при наличии покупки за последние 180 дней отклоняются; 100% входов тех же людей без кода проходят.
- **SC-005**: 100% попыток входа с кодом при отсутствии покупок за 180 дней (и валидном коде) завершаются реактивацией и стартом скидки.
- **SC-006**: При покупке приглашённого внутри 7 суток приглашающий в 100% случаев получает ровно один пакет награды (купоны и/или кешбек по зафиксированным значениям); при отсутствии такой покупки доля наград равна 0.
- **SC-007**: Пока скидка активна, 100% предварительных расчётов и зафиксированных чеков приглашённого учитывают реферальную выгоду (если она не проиграла более выгодной скидке на позицию); после истечения окна доля чеков с этой скидкой равна 0.
- **SC-008**: 95% пользователей на экране входа с первого раза понимают, что код необязателен, и почему вход с кодом отклонён (невалидный код или «недавно были покупки — войдите без кода»).
- **SC-009**: Самоприглашение и повторная активация одного кода не проходят в 100% попыток, включая одновременные.
- **SC-010**: Экономия приглашённого по реферальной скидке и кешбек приглашающего выражены в рублях в тех же местах, где пользователь уже видит экономию и баллы — без отдельной «игровой» валюты.

## Assumptions

- «Таймаут» в постановке — это не истечение сессии, а отсутствие покупок 6 месяцев. Реактивация = вход существующего пользователя с реферальным кодом при выполнении этого условия.
- 6 месяцев = 180 календарных суток назад от момента входа с кодом, в часовом поясе продукта (по умолчанию Europe/Moscow).
- «Неделя» = 7 × 24 часа от момента активации, не календарная неделя с понедельника.
- Код одноразовый и каждый раз новый. Один код — один друг. Неиспользованные коды не сгорают в PoC.
- Формат кода — ровно 6 символов из алфавита `[A-Za-z0-9]`. Регистр значим (см. Clarifications).
- Регистрация и вход без кода не меняются по смыслу относительно существующей авторизации по телефону.
- Активировать код можно только в момент регистрации или входа, не из уже открытой сессии.
- X%, число купонов и сумма кешбека в рублях задаются настройками окружения. Значения по умолчанию для демо: **скидка 10%**, **2 купона**, **кешбек 50 ₽**.
- Кешбек приглашающего использует существующий счёт баллов (спека 007). Купоны — существующий счёт купонов колеса (спека 009).
- Реферальная скидка — персональная процентная скидка на позиции чека, а не скидка на итог после баллов. Соревнование с другими скидками — best-price-wins (спека 005).
- Квалифицирующая покупка — любой успешно зафиксированный чек приглашённого, привязанный к его карте лояльности, в том числе с нулевой суммой к оплате.
- Отдельная промышленная антифрод-система (совпадение банковских карт и т.п.) вне скоупа; достаточно запрета самоприглашения, одноразовости кода, фильтра 180 дней и разовой награды за связку.
- Рассылка SMS/push с кодом не делается: пользователь сам отправляет код через системный share или копирование. Интеграции с кассами и CRM X5 нет — покупки и вход имитируются, как в конституции.
- На экране статусов приглашений достаточно кода и статуса; показывать телефон друга не нужно (принцип V).
- Конституция относит реферал к концептуальному скоупу демо и запрещает новые игровые механики сверх аватара, челленджа и рейтинга. Эта функция добавляется явно как канал возврата и приглашения в программу лояльности: выгода обеих сторон выражена в рублях (скидка и кешбек) и в купонах, которые уже конвертируются в рублёвую экономию на колесе. Перед показом жюри как «готово к пилоту» нужен расчёт юнит-экономики (принцип IV): стоимость скидки X% + купоны + кешбек ≤ ожидаемый прирост маржи от новой или вернувшейся покупки.
- Смена телефона, передача неиспользованного кода другому приглашающему, покупка кодов и ручной ввод кода из профиля уже вошедшего пользователя — вне скоупа.
