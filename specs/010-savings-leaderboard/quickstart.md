# Quickstart: Лидерборд экономии магазина

## Предусловия

```bash
cd web
docker compose up -d postgres
poetry run alembic upgrade head
```

Нужны `USER_TOKEN` (JWT пользователя A) и возможность создавать чеки через терминал (`X-Terminal-Token`, `POST /receipts`) либо сид/фикстуры с `loyalty_card_id`, `store_id`, позициями и датами.

Базовый URL: `http://localhost:8000`.  
Месяц в проверках — текущий календарный месяц `Europe/Moscow`.

Контракт ответа: [contracts/api-contracts.md](contracts/api-contracts.md).  
Правила home store и процента: [data-model.md](data-model.md).

## Сценарий 1: 401 без токена

```bash
curl -i http://localhost:8000/leaderboard
```

Ожидание: **401**, тела рейтинга нет.

**Требования**: FR-003, SC-008 (нет утечки чужих строк).

---

## Сценарий 2: Нет покупок — пустое состояние

Пользователь без чеков:

```bash
curl http://localhost:8000/leaderboard \
  -H "Authorization: Bearer $USER_TOKEN"
```

Ожидание: **200**, `status == "no_home_store"`, `store == null`, `me == null`, `entries == []`, `participant_count == 0`.

**Требования**: FR-005, FR-019, SC-005.

---

## Сценарий 3: Home store по 20 покупкам

У пользователя A ровно 20 чеков: 12 в магазине А, 8 в магазине Б (оба с `store_id`).

```bash
curl http://localhost:8000/leaderboard \
  -H "Authorization: Bearer $TOKEN_A"
```

Ожидание: `status == "ready"`, `store.id` = магазин А. Повтор запроса — тот же `store.id`.

Укороченный набор: 9 чеков, 5 в А → тоже магазин А.

Ничья 10 / 10: побеждает магазин с более поздней покупкой.

**Требования**: FR-004, FR-005, FR-006, SC-004.

## Сценарий 4: Процент выше рублей

Два пользователя, один home store.

| Пользователь | Экономия месяца | База месяца | Ожидаемый % | Ожидаемое место |
|--------------|-----------------|-------------|-------------|-----------------|
| A            | 200 ₽           | 2 000 ₽     | 10          | выше B          |
| B            | 500 ₽           | 10 000 ₽    | 5           | ниже A          |

Запросы от A и от B: у A `me.rank < me.rank` B, `me.savings_percent == 10`, у B `== 5`. В `entries` нет полей, заменяющих процент рублями.

Третий пользователь C с home store другого магазина и процентом 50 в список A/B не входит.

**Требования**: FR-007, FR-009, FR-010, FR-012, SC-002, SC-003.

---

## Сценарий 5: Зритель вне топ-10 и общее место

≥ 11 участников одного магазина с разными процентами, зритель — 11-й.

Ожидание: `len(entries) == 10`, все `is_me == false`, `me.in_top == false`, `me.rank == 11`, `participant_count >= 11`.

Два участника с одинаковым округлённым процентом: одинаковый `rank`, схема 1, 2, 2, 4.

**Требования**: FR-013, FR-016.

---

## Сценарий 6: Нет покупок в текущем месяце

Home store есть по чекам прошлого месяца, в текущем месяце чеков нет.

Ожидание: `status == "ready"`, `store` заполнен, `me == null`, `entries` без зрителя, нет `savings_percent: 0` у `me`.

**Требования**: FR-011, FR-015, FR-019.

---

## Сценарий 7: Мобильный вход

1. Войти в приложение, открыть вкладку Аппи.
2. Нажать на блок «Экономия по месяцам» (график + сводка).
3. Открывается экран рейтинга: имя магазина, «N из M», процент, список.
4. Назад — снова Аппи, скролл блока статистики на месте.
5. Без сети / 5xx — текст ошибки и кнопка повтора, Аппи не теряется.

**Требования**: FR-001, FR-014, FR-015, FR-019, SC-001, SC-006, SC-007.

## Сценарий 8: Анонимность

В любом 200-ответе с `entries`: нет ФИО, телефона, адреса, `user_id`. Чужие `label` вида `Покупатель ###`.

**Требования**: FR-018, SC-008.
