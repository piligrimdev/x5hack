## Примечания

- **Уточнения завершены (2026-09-05)**:
  - Развертывание Langfuse: self-hosted в docker-compose (не облако SaaS)
  - Labels структурированных логов: service_name, user_id, request_id, procedure_name, procedure_state (обязательные для всех сервисов)
  - Метрики Prometheus: оба стандартные HTTP метрики И custom application метрики
  - Дашборды Grafana: три отдельных сфокусированных дашборда (API Health, Очередь Celery, Использование LLM & Затраты)
  - Контекст пользователя LLM трейса: извлекается из контекста запроса через contextvars
- Спецификация включает 4 P1 пользовательских сценария, покрывающих основные мониторинг сценарии и 1 P2 сценарий для видимости очереди worker
- Четкие границы: политики retention, alerting, развертывание Kubernetes явно отмечены как out-of-scope для v1
- Критерии успеха измеримы и теперь включают специфичные требования дашбордов и queryability labels
- Граничные случаи покрывают сценарии недоступности сервиса и требования graceful degradation
- Готово к `/speckit-plan` с деталями реализации теперь уточненными
