# X5 Loyalty Hack — Constitution

## Core Principles

### I. Экономия как единая видимая метрика

Всё взаимодействие пользователя с продуктом ДОЛЖНО быть сосредоточено вокруг
одной цифры — сколько рублей сэкономлено. Аватар, челлендж и рейтинг ОБЯЗАНЫ
выражаться в рублях, а не в абстрактных баллах активности.

Механики без прямой связи с измеримой экономией ЗАПРЕЩЕНЫ. Дашборд экономии —
обязательный элемент UI, не опциональный виджет.

### II. Минимальный когнитивный барьер (NON-NEGOTIABLE)

Любая механика ДОЛЖНА быть доступна за ≤2 действия от главного экрана. Ни один
экран НЕ МОЖЕТ требовать от пользователя «разобраться» перед использованием.

Добавлять новые вариации механик (игры, ускорители, колёса, параллельные ачивки)
поверх трёх выбранных (аватар, челлендж, рейтинг) ЗАПРЕЩЕНО.

### III. ИИ-персонализация с верифицируемым hit rate

Персональный челлендж ДОЛЖЕН генерироваться ИИ-агентом по истории покупок
конкретного пользователя. Шаблонные (одинаковые для всех) челленджи ЗАПРЕЩЕНЫ.

Целевой стандарт: hit rate ≥70% на 30–50 синтетических профилях. Разметка
эталонных ожиданий ДОЛЖНА быть заморожена до тюнинга модели. Разметчик и тюнер
ДОЛЖНЫ быть разными людьми.

### IV. Экономическая обоснованность — приоритет наравне с UX

Стоимость награды ДОЛЖНА быть ≤ ожидаемый прирост маржи при заявленных
допущениях. Каждая механика ОБЯЗАНА сопровождаться расчётом юнит-экономики
до попадания в финальный прототип.

Механики без экономического обоснования НЕ демонстрируются жюри как
«готовые к пилоту».

### V. Privacy by Design — рейтинг без личных данных

В публичном рейтинге ЗАПРЕЩЕНО использовать ФИО, адреса, номера телефонов
или любые прямые идентификаторы. Единица агрегации — дом или район.

Синтетические данные ДОЛЖНЫ генерироваться без реальных персональных данных X5.
Анонимизированные образцы от кейсодателя — только как калибровочные параметры.

## Технические ограничения (PoC/Хакатон)

- Нет интеграции с production-системами X5: кассы, CRM, push — имитируются.
- Только синтетические данные; реальные ПД вне скоупа.
- Стек зафиксирован: мобильный фронт — Expo/React Native (TypeScript),
  бэкенд — Python + LLM API. Смена требует явного командного решения.
- Скоуп демо: 3–4 экрана (аватар, челлендж, рейтинг). Реферал — концептуально.
- Антифрод: опционально; при реализации — сигнал 4 последних банковских карт.

## Backend Technical Standards

Применяется к Python-бэкенду (`web/`, `src/**/*.py`, `Dockerfile`, `pyproject.toml`).
Детальные паттерны — в `.claude/rules/scripts-and-services.md` и
`.claude/rules/fastapi-rest-api.md`.

### Архитектура RSI

Бэкенд ДОЛЖЕН следовать слоям Repository–Service–Interface:

| Слой | Каталог | Ответственность |
|---|---|---|
| Repository | `crud/` | Доступ к данным (SQLAlchemy / `.json`) |
| Service | `services/` | Бизнес-логика, валидация, запуск jobs |
| Interface | `routes/` | FastAPI endpoints; только schema + session → service |

FastAPI-сервис ДОЛЖЕН быть отдельным пакетом под `src/`. Смешивать API-роуты
со скриптами (`rag/`, `data/scripts/`) ЗАПРЕЩЕНО.

### Dependency Injection

Сервис ДОЛЖЕН получать репозиторий через аргументы или FastAPI `Depends`.
Создавать репозиторий внутри сервиса ЗАПРЕЩЕНО.

### Контролируемая инициализация

Модули `crud/`, `services/`, `routes/`, `entities/` НЕ ДОЛЖНЫ иметь side effects
на уровне импорта. Вся сборка — в `core/`, `main.py` или `lifespan`.

### Зависимости и логирование

- Зависимости: Poetry (`pyproject.toml` + `poetry.lock`). `pip install -r` ЗАПРЕЩЁН.
- Скрипты: `print`. Сервисы и DAG-код: `structlog`. Смешивать ЗАПРЕЩЕНО.

### Тесты

`tests/` зеркалирует `src/`. Unit-тесты покрывают слой Service.

## Mobile Technical Standards

Применяется к мобильному приложению (`x5mobile/`). Перед написанием кода
ОБЯЗАТЕЛЬНО читать актуальную документацию Expo v57:
**https://docs.expo.dev/versions/v57.0.0/**

*Обоснование:* Expo меняет API между мажорными версиями; код по устаревшим
паттернам сломается при сборке.

### Стек и платформы

- **Expo v57** (managed workflow) + **React Native** + **TypeScript** (strict)
- Целевые платформы: **iOS и Android**. Web — вспомогательно (только для
  быстрой проверки в браузере во время разработки).
- Навигация: **Expo Router** (файловая маршрутизация, аналог Next.js App Router)
- Анимации: **React Native Reanimated**

Выходить из Expo managed workflow (eject) ЗАПРЕЩЕНО в рамках PoC.

### Структура пакета

```text
x5mobile/
  src/
    app/          # Expo Router — страницы (_layout.tsx, index.tsx, ...)
    components/   # переиспользуемые UI-компоненты
    constants/    # тема, отступы, цвета
    hooks/        # кастомные React-хуки
  assets/         # изображения, иконки, шрифты
  app.json        # конфиг Expo
  tsconfig.json
  package.json
```

Бизнес-логика ДОЛЖНА быть в хуках (`hooks/`) или отдельных сервисных модулях,
а не встроена в компоненты страниц. Компоненты — только UI + вызов хука.

### Паттерны разработки

- Все новые компоненты — **функциональные** с TypeScript-типами; class-компоненты
  ЗАПРЕЩЕНЫ.
- Стили — через `StyleSheet.create` или совместимые решения (без inline-объектов
  в JSX без мемоизации).
- Навигация между экранами — через Expo Router (`<Link>`, `router.push`);
  прямой импорт `react-navigation` без Expo Router ЗАПРЕЩЁН.
- Нативные зависимости, требующие `pod install` / `npx expo prebuild`, ДОЛЖНЫ
  быть явно задокументированы в README перед добавлением в `package.json`.

### Зависимости

- Управление: **npm** (уже настроен). Не добавлять yarn/pnpm без командного решения.
- Нативные пакеты ДОЛЖНЫ быть совместимы с Expo SDK 57 (проверять через
  https://docs.expo.dev/versions/v57.0.0/ или `npx expo install`).
- `npx expo install <пакет>` предпочтительнее `npm install` для нативных пакетов —
  устанавливает версию, совместимую с текущим SDK.
